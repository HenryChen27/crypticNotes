# 地图匹配算法改进待办（2026-11-06，未开始）

依据：`failure-records` 87 条本地记录的统计，以及两张截图的离线对照实验。详细数字见当时的分析；这里只记结论和顺序。

## 失败分布
- 22 条是在游戏外按了快捷键，截的是桌面，门控正确拒绝。
- 15 条前两名 explained 差 < 0.03（相似房间歧义，二层小房间为主）。
- 25 条可见角点 ≤ 40（刚进二层、探索很少）。
- 11 条前景几乎为空（楼层没探索）。
- 3 条仅因 `retrieval_score < 4` 被拒，其中一条 explained 0.82 / contradiction 0。
- 耗时中位 347 ms、p90 659 ms，速度不是瓶颈。

## 待办（按建议顺序）
1. **建评测集**：从 `failure-records` 的截图标注真值（地图、楼层），实现 `mapmatching/benchmarks/README.md` 里的评估计划，用 ROC 定阈值。
2. **证据门按可见角点归一化**：`retrieval_score < 4` 对 16 个角点的画面不公平；空白楼层在提取阶段用前景面积直接判「楼层未探索」。
3. **快捷键前台校验**：`is_game()` 不看标题，聊天里打 g 就整屏截图；开图前用 `find_game_window` 校验前台。隐私问题。
4. **验证容差随缩放放大并封顶**（`verification.verify` 固定 2.5 px）：实验显示封顶 1.5 倍能救回缩放 2.05 的失败案例且不翻转 4.7 倍的成功案例，但后者领先幅度从 0.04 缩到 0.02，必须在评测集上定值。
5. **反向证据**：验证是单向的，参考图在已探索区域内本该出现却没出现的墙不扣分；加上这项才能分开相似房间。描述子（12×12 占用格）可补边界链形状或线段方向直方图。
6. **雾掩膜**：`fog_mask_available` 一直是 False，雾的软边界进了 boundary，contradiction 偏高。

第 4 到 6 项属于「影响判定输入」的改动，需要先有评测集。
