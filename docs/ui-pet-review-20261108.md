# 桌宠与双端界面评估（2026-11-08，仅分析）

依据：`mapmatching/appearance/`、`mapmatching/theme.py`、`android/.../Theme.java`、`docs/images/` 里的实跑截图、用户提供的游戏内地图界面截图（手机与 PC 客户端），以及对主流桌宠的联网调研（Shimeji 系、Desktop Goose、VPet 虚拟桌宠模拟器、Desktop Mate、Screen Pet Engine、桌宠屋、魔法桌宠）。

## 一、桌宠：和主流作品比，我们有什么、缺什么

主流桌宠大致分三派：**陪伴派**（Shimeji、Desktop Mate、Screen Pet Engine）靠"活在桌面上"——沿任务栏走、爬窗、坐在窗口顶上、随鼠标；**养成派**（VPet、桌宠屋）靠数值——饥饿/心情/体力、工作、商店、成长阶段、好友互赠，近两年加上 LLM 聊天模组；**工具派**（魔法桌宠）把桌宠当快捷入口——开网页、存片段、翻译、创意工坊扩展。

我们的定位是第三派加一点第一派：它是识图助手的脸，顺带有陪伴感。按这个定位，现在已经有的（骨骼分层动画、小动作调度、打盹/唤醒、拖动物理、脚下阴影、气泡、右键菜单、两套皮肤、技能特效）在"工具型桌宠"里已经是上游水平。真正缺的是下面几项，按性价比排序：

1. **对游戏状态的反应，而不只是对识图结果的反应。** 桌宠现在只听识图消息。它应该知道"游戏在不在前台""地图开没开""这局打了多久"：游戏切到后台时趴下打盹，开图瞬间抬头，连续识别成功 N 次露个得意的动作，一局结束（地图长时间没开）伸懒腰。这些信号 `game_scene_watch` 和 `live` 里都已经有，只缺接到 `PetBehavior`。这是陪伴派最核心的"它在看着我玩"的感觉，成本最低。
2. **窗口感知。** Shimeji/Screen Pet Engine 的招牌是坐在窗口顶边、沿任务栏走。我们的素材只有正面视角，走路不现实，但"挂在游戏窗口上边缘"（被线吊着轻晃）和"落在任务栏上"这两个姿态各一张图就能做，矿灯更简单——它本来就悬浮，只需把悬浮高度贴到窗口边。
3. **鼠标穿透/专注模式。** Screen Pet Engine 和桌宠屋都有"免打扰"档：宠物继续动但不吃点击。我们有「安静模式」「空闲淡出」「锁定位置」，缺"点击穿透"这一档——打团时宠物挡在地图上又不想关它，这是真实需求。
4. **两只宠物同屏互动。** 布偶和矿灯是切换关系。Shimeji 的乐趣一半来自多只互动。让两只同时在（矿灯照着布偶、布偶被激光吓一跳、两只贴脸互看），每种 1 个动作就够，复用现有特效。
5. **更多反馈通道。** 现在只有气泡文字。主流做法还有：托盘图标随情绪换脸、Windows 通知用桌宠头像、识别失败时气泡给"下一步建议"按钮（比如「切换作者」「重新识别」）而不是纯提示。
6. **可定制。** Shimeji 的 XML 行为表、VPet 的创意工坊说明用户愿意改。我们可以先开放最便宜的：皮肤目录放一张新原图 + `rig.py` 多边形即可注册，再加一个「动作频率」滑杆。
7. **明确不做的：** 数值养成（饥饿/工作/商店）与游戏助手定位冲突，会变成第二个游戏；AI 聊天在对局里没人用；走路/翻身需要新视角素材，收益不如上面几条。

## 二、界面：对照第五人格的地图界面，还差什么

先说结论：粉笔/雾面这套已经抓住了游戏地图界面的骨架——深蓝灰半透明底、细颗粒、浅灰选中块+深色字、薄描边、`HYDiWRGJ` 本身就是游戏字体。差的是"精细度"而不是方向。对照截图逐项看：

**1. 图标语言。** 游戏里每个条目前都有一枚白色线稿图标（矿车密道、冶炼炉、出口、异象），文字是配角。我们的面板全是文字行。最该补的是一套 20 个左右的单色线稿图标：难度、作者、叠图、识别、楼层、桌宠、快捷键、录屏、小游戏。线稿风格统一用 1.5 px 白线、少量 45° 斜切角，和游戏一致；红色只给危险项（退出、移除地图），对应游戏里「异象」的红。

**2. 层级与留白。** 游戏面板信息密度低：标题 17 px 左右、条目之间留一行、分组用一条细线而不是框。我们的桌面面板为了放下所有设置，行距偏紧、分组标题和正文对比弱（见 `panel.png`）。建议把「地图/作者/难度/路线」收成一个"本局"卡片放最上面，其余全部折进「更多」，默认只露 5 行以内。安卓首页已经这么做了，桌面端还没有。

**3. 选中态与按下态。** 游戏的选中块是实心浅灰纹理块、四角微圆、文字反色，按下时整块略暗并下沉 1 px。我们的 `ChalkChoice` 已经是这个样子，但按钮（`ChalkButton`）按下没有反馈、悬停没有变化，鼠标用户会觉得"没反应"。加 80 ms 的按下变暗和 1 px 位移即可。

**4. 边框装饰。** 游戏面板用的是"破边"而不是描边：边缘有一圈被擦掉的粉笔质感，四角偶尔有一小段手绘线。我们 `chalk_texture` 的羽化边已经接近，可以再加：面板四角一小截 L 形手绘线（深灰 40% 透明）、标题下一条不规则细线（像 `Theme.Rule`，但用手绘笔触图而不是直线）。只要两张小图。

**5. 快捷键提示。** PC 客户端在按钮旁标 `ESC`、`G`、`Ctrl`、`Shift` 这样的小方块键帽。桌面端我们有 G/ESC 快捷键但只在设置里有文字；把键帽样式（细描边小方框、等宽字）做成 `KeyCap` 控件，放在「重新识别 G」「关闭 ESC」按钮右侧，既像游戏又省了说明文字。

**6. 叠图层本身。** 游戏地图是蓝灰走廊+褐色房间+深色围墙，我们叠上的作者图是另一套配色（展十的蓝/褐/黑、凉哈皮的游戏截图+黄框+红线）。两者并排时作者图像"贴纸"。可以给叠图层加一个"融入"模式：把作者图的黑底去掉只留地形与路线（展十的 `zhanshi_mask` 已经能分出地形），路线线条加 1 px 深色描边保证在亮区可读；或者至少把叠图的透明度默认从 30% 调到按亮度自适应。

**7. 悬浮球与气泡（安卓）。** 悬浮球白纹章+气泡从球里长出来的交互已经很好，但气泡的底是通用深色条。改成和地图面板一致的粉笔条（`Theme.MistDrawable` 已有）并给结果文字前加一枚线稿图标（对勾/问号/楼层），一眼能分清"成功/失败/换层"。另外识别中纹章旋转可以换成游戏里"加载"的那种断续转动（转 120° 停一下），更像游戏。

**8. 双端一致性。** 桌面端用 `ModuleNavigation` 上方标签切「手记/小游戏」，安卓用 `settingsTab/gamesTab`；两端文案、顺序、折叠分组命名略有出入（桌面「个性外观」、安卓「辅助设置」）。建议做一张"设置项清单"把两端的分组名、顺序、帮助文案统一，再各自实现。

**9. 动效。** 游戏面板是淡入 + 轻微上浮 150 ms，关闭反向。我们桌面面板是直接显示/隐藏。Qt 侧用 `QPropertyAnimation` 做透明度+6 px 位移，安卓侧用 `ViewPropertyAnimator`，各 20 行。

**10. 可访问性细节。** 游戏字体在 13 px 以下笔画会糊，手机端小字标签（帮助文案 12–13 px）读起来吃力；帮助文案改成点击标题才展开的"说明"，默认收起，字号不低于 14 px。

## 三、建议的顺序

1. 线稿图标集 + 键帽控件 + 按下反馈（视觉提升最大，半天到一天）。
2. 桌面面板信息架构：本局卡片 + 折叠「更多」（半天）。
3. 桌宠接游戏状态：后台打盹、开图抬头、连胜得意（半天）。
4. 面板淡入上浮、气泡换粉笔底 + 结果图标（半天）。
5. 点击穿透档、挂在窗口边缘的姿态（一天）。
6. 两宠同屏互动、叠图"融入"模式（各一天，可后置）。

每一项都不碰识图核心；1、2、4 是纯外观，可以随下一个版本一起发。
