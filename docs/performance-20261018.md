# 性能优化与崩溃排查（本地测试）

默认启用：Windows 窗口采集在线程结束后断开回调引用，避免完整截图等待循环垃圾回收，并把 native stop/wait 移出 GUI 线程。Windows/macOS 识图进程仅缓存最近一张地图原图；布偶与等待符号共用刷新计时器。Android 相同控件短期复用门控结果，相同地图证据短期跳过重复匹配；新线索、楼层变化、手动重试、强行叠图会失效或绕过复用。签名缩图改为批量读取像素。

省电模式默认关闭：桌面在设置中开启后，输入轮询由 20ms 调整到 40ms、可见性检查由 0.8s 调整到 1.6s、布偶刷新约减半。Android 在 App 的辅助设置中开启后降低自动检查频率；小游戏重新打开后最多请求 60Hz，呼吸动画缓存由 48×160² 改成 24×128² 的像素上限，理论单种素材缓存上限降低约 68%。游戏物理计算和源图不变，但呼吸动画更粗、自动检查反应稍慢。手动重新识别绕过重复匹配等待。

检查了用户提供的 83 条识图记录和 UI 事件日志，没有发现 Python/原生崩溃堆栈；识图失败记录不是崩溃转储，不能认定本次闪退由某个匹配结果导致。发现并修复的窗口采集循环引用属于可复现资源隐患，仍需用户实机确认是否解决此次崩溃。新增 native-desktop.log / native-matcher.log 留存支持的原生异常堆栈。

实际测试：同一台 Windows 设备，关闭 Python 自动垃圾回收，连续采集 20 次。已发布旧版残留 20 个截图对象，修复版残留 0 个；修复版测试约 2.1 秒。此结果证明资源释放改善，不代表整机温度降低比例。手机发热、长时间稳定性和 Mac 实机表现尚待实测。

详细数据：out/performance-20261018/capture-before-after.json、capture_stress.json。

## 追加：拒绝截图授权

用户补充拒绝授权后出现英文报错和整机黑屏。查到原窗口采集失败会自动回退桌面采集。现对可识别的拒绝/取消授权错误停止采集并阻止后续重复创建原生会话，只有用户点击重新识别才允许再次尝试。界面显示短中文，原始错误写入 ui-events.jsonl。最多同时持有两个短期截图会话；原生线程未确认退出时不销毁其回调。小游戏背景检测停止时也异步等待原生线程退出并清理回调。

拒绝授权并不应导致系统黑屏。现有材料没有系统级故障记录，不能确认驱动超时、系统资源耗尽或其他原因；需故障时间和可靠性监视器问题名称进一步关联。拒绝权限回归测试证明不会调用桌面截图回退；真实截图压力测试仍为 20 次、零残留对象。
