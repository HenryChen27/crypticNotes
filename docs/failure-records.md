# 收集识别案例

设置中的「记录识别案例」默认开启，可随时关闭；点击「打开记录」定位目录。打包版在 `%LOCALAPPDATA%/IdentityVMapAssistant/failure-records`，源码版在项目的 `failure-records`。

每次识别没有通过叠图条件时，保存一条本地记录。目录按「未发现地图结构」「无法配准」「匹配证据不足」「候选地图相似」「楼层不确定」「叠图生成失败」「程序异常」分类。分类是算法拒绝的原因，不代表已经确定实际根因；未打开地图的截图也可能归入未发现地图结构。

每个时间编号文件夹包含：

- `screen.png`：送入算法的无损截图，便于复现。
- `record.json`：分类、时间、难度/人数、截图尺寸、缓存地图、候选得分与配准参数、算法诊断和地图登记表/可用源码的 SHA-256。

成功案例也保存到「识别成功」，每个分类独立保留最近 20 条（单类容量上限 500 MB），超出自动删除时间最早的案例。旧目录超限时，下次记录会一并清理。同类结果 30 秒内最多写一次，相同截图在当前工作进程内去重；保存失败不影响识图。

记录包含程序版本、触发原因（地图键、恢复显示键、手动重试、鼠标跟随、关闭确认）和请求编号。实时屏幕先检查右上关闭按钮及右下全览图标，未确认时归入「未确认地图展开」，不再运行地图匹配。diagnostics.map_ui 保存两个控件的检测分数；检测失败也可能是控件被遮挡或游戏界面布局改变，不等同于确定关闭。本地截图测试不要求带游戏界面，标记为 unknown。

协作者点击「打开记录」，检查截图中是否包含不想分享的信息，将整个 `failure-records` 文件夹压缩后发给开发者即可。不自动上传、不采集密钥或账号设置。清理或移走旧记录后可继续收集。

「识别成功」表示算法接受结果，不代表人工确认正确或该帧最终显示；可用于分析误匹配，建议同时附上错误叠图截图。截图获取失败、进程强制终止时可能没有记录。分析时使用匹配版本的地图库，结合 JSON 候选和诊断重新运行算法。
