# 收集识别失败案例

设置中的「记录识别失败」默认开启，可随时关闭；点击「打开记录」定位目录。打包版在 `%LOCALAPPDATA%/IdentityVMapAssistant/failure-records`，源码版在项目的 `failure-records`。

每次识别没有通过叠图条件时，保存一条本地记录。目录按「未发现地图结构」「无法配准」「匹配证据不足」「候选地图相似」「楼层不确定」「叠图生成失败」「程序异常」分类。分类是算法拒绝的原因，不代表已经确定实际根因；未打开地图的截图也可能归入未发现地图结构。

每个时间编号文件夹包含：

- `screen.png`：送入算法的无损截图，便于复现。
- `record.json`：分类、时间、难度/人数、截图尺寸、缓存地图、候选得分与配准参数、算法诊断和地图登记表/可用源码的 SHA-256。

同类失败 30 秒内最多写一次，相同截图在当前工作进程内去重。最多 100 条或 500 MB，满后停止新增，不删除已有记录。进程重启会重置限频记录，但容量限制不变。保存失败不影响识图。

协作者点击「打开记录」，检查截图中是否包含不想分享的信息，将整个 `failure-records` 文件夹压缩后发给开发者即可。不自动上传、不采集密钥或账号设置。清理或移走旧记录后可继续收集。

这是自动失败采样，无法自动发现「算法判定成功，但实际上叠错图」。该情况请另附原截图与错误叠图截图。截图本身获取失败、进程被强制终止时可能没有记录。分析时使用匹配版本的地图库，结合 JSON 候选和诊断重新运行算法。
