# 新增地图与噩梦模式

## 噩梦怎么用

重启助手，选择「噩梦」和「单人 / 多人」，打开游戏地图后按设定的快捷键。
当前内置两种模式各 13 张地图，支持 2F、1F 和地下室，自动判断当前楼层并只叠出该层。
原图按当前配准结果缩放、平移，再使用用户设置的不透明度显示。

本次补的是缺失的楼层元数据，没有放宽可靠性门槛。探索太少、候选相似、楼层不明时仍拒绝叠图。
原图合成测试 78/78 的身份和楼层正确，78/78 生成叠图；已知变换下选区四角的最大误差，
跨场景中位数 0.80 px、P95 4.39 px、最差 6.67 px。
这些数字只衡量合成场景，不是噩梦实战精度。需要真实单人/多人地图截图（含不同楼层及迷雾）继续验证。

## 单张图片录入

1. 展开齿轮，点击「管理地图」，再点对话框底部的「新增地图」。
2. 点击「选择原图」，选择完整的路线图或地图原图，输入地图名称。
3. 选择困难 / 噩梦；噩梦还需选择单人 / 多人。同一张图不会自动用于所有模式。
4. 选择 1F、2F 或地下室，在预览上拖动框选完整的对应楼层。图片只有一层时，可直接点击「整张为此层」。框错了就重画或「清除此层」。
   长图可滚轮缩放（以鼠标位置为中心），空格 + 左键拖动或中键拖动平移；「适应窗口」恢复全图。缩放和平移只影响预览，标注始终保存为原图坐标。
5. 多层拼图逐层框选。选区允许重叠，适用于楼层交错排版；尽量减少额外内容，叠图会保留选区内的原图像素。
6. 点击「保存并入库」。保存完成后，不用重启，在对应难度/人数下自动参与识别。

图片应清晰、未旋转、含完整地图结构，色调与当前游戏灰蓝地图相近。
任意手绘图、不同画风或有大量遮挡的游戏截图，不保证能识别。不要把未探索的残缺截图当作完整地图原图。

仅把文件粘贴到目录不够：系统还需要难度、人数、楼层范围和提取好的结构特征。
新增入口会自动完成这些步骤；原始文件不会被移动或修改。
重复名称或相同图片会提示重复，避免两个相同候选互相干扰（**跨难度、跨人数也算重复**：
现在只有一棵地图库，同一张图挂两个模式只会让两边都匹配到它）。

## 保存位置与备份

所有和地图有关的东西都在 `maps/` 这一棵树里，不再分「内置」和「自建」：

```
maps/
├─ hard/                      困难原图
├─ nightmare/solo/            噩梦·单人原图
├─ nightmare/duo/             噩梦·多人原图
├─ _unindexed/                放进来但**没有登记**的图，不参与匹配
├─ floors.json                登记表：每张图的难度、人数、楼层框、来源
├─ disabled.json              被移除的条目，原样存放，恢复就是搬回去
├─ index.json                 索引缓存（派生物，可重建）
└─ evidence/<16位十六进制>.npz 每张图的特征（派生物，可重建）
```

原图文件**字节原样**保存，绝不重编码 —— 索引里记的是文件哈希，
重编码会让它和 `benchmarks/` 的样例静默对不上。

**登记才是关键，粘贴不是。** 一张图只有同时满足「文件在 `maps/<难度>/[<人数>/]` 下」
和「`floors.json` 里有一条同名条目」才会参与匹配。所以：

- 往 `maps/` 里直接粘贴文件**不会**让它被识别，它只是躺在那里；
- 想让它参与匹配，必须走「管理地图 → 新增地图」这一步（它会自己把图复制进去）；
- 想让它停下来，走「移除」；原图和特征都留在盘上，随时能恢复。

要备份就整份备份 `maps/`。不要手动替换里面的图片而不重新录入，
否则图片会和 `evidence/` 里的特征对不上。

如果只改了楼层框（没换图），不需要重新录入，跑一次
`python -m mapmatching build-index` 重建索引即可 ——
列表里那一行会显示「需重建索引」，就是提醒这件事。
