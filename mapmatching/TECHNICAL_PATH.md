# 以认对地图、对准道路为目标的技术路径

## 当前更新

用户明确提供开局模式后，已将该信息改成必填 session context。现有困难样本的最终候选和楼层均为 6/6，41 个独立人工标记点初步测得每图 RMS 1.49–4.85 px（含标注误差）。28 张 Hard 已加入楼层/插图元数据；离线叠图模块、CLI 与六图交互展示已完成。生产拒识校准、噩梦实测、游戏内悬浮层仍未完成。以下步骤保留此前研究路径背景，最新实测以 progress_overlay.md 为准。

当前只是能运行的匹配原型：6 张开发截图中，正确图全部进入 Top-5，局部配准后排第一的是 4/6。未验证楼层、尺度和平移误差，没有屏幕叠加。两套原始地图和 examples 直接使用，旧代码保持隔离。

## 1. 先让认图有可靠依据

继续使用局部墙体与房间布局，保留多个候选，再检验它们能否解释当前可见部分。现在的空间一致性消融使 Top-5 从 6/6 降至 4/6，支持保留局部几何关系。不能用整图颜色、面积或全图相似度做身份判断。

当前两例失败在跨难度相似局部。地图未探索部分不能用来排除候选；若现有截图不足以区分，就应 UNKNOWN。用户明确知道的 difficulty/mode 可作为显式输入，但不能从 example GT 偷取。增加未见地图和相似局部截图，按 map 分开发/校准/测试，不能把六图结果当泛化能力。

## 2. 独立验证对齐，不能拿算法自己的答案当标准

给每张 reference 标注楼层主图区域和插图排除区域；Hard 楼层上下顺序有差异，Nightmare 有地下室。保留裁剪偏移和缩放，最终坐标统一还原到原图和完整截图。当前 baseline 把完整 reference 作为画布，仅适合初步实验。

为截图独立标注分散的对应点、floor 和标注误差。用这些点测尺度误差、平移误差及重投影像素 RMSE。没有可靠标注时这些指标必须为 null，不把候选 pose 当成 GT。

局部点间距离给有限尺度假设，稀疏几何投票给平移；只让 Top-K 进入精细配准。验证只检查可见游戏结构，未知区域不扣分。将 glow/fog 边界与稳定墙体区分，替换当前固定 ROI 布局先验和简单颜色分离。

## 3. 再允许自动锁定

在独立校准集上评估可见结构支持、矛盾率、最佳/次佳差距和错误接受率。不能用六个开发样本调一个恰好全对的阈值。报告 UNKNOWN、wrong-lock/all、wrong-lock/accepted 和接受覆盖率；永远 UNKNOWN 的零错锁不代表功能完成。

已有 MatchSession 接口只为后续保留生命周期：可靠 MATCHED 才 LOCK，显式 rematch/unlock 才更换。当前 baseline 不会返回 MATCHED。

## 4. 最后验证实际叠加是否能用于找路

认图和对齐通过后，使用同一个原图到截图的坐标变换呈现标准路线；通过已知路口、门和墙角检查叠加误差。误差容限需由实际显示需求确定。截图缩放、窗口尺寸、地图 zoom/平移和楼层切换都要覆盖。该层当前尚未实现，原需求本阶段也明确排除了 overlay/UI。

## 5. 性能与数据门槛

目前完整新进程中位时间约 1.67 秒，不满足 cold <500ms。先满足正确率，再优化索引加载、全局近邻检索和稀疏投票；保留 Top-K 配准，不靠少看地图或降低正确率换速度。

需补不同 Hard/Nightmare、solo/duo、每层、不同位置/zoom/fog/探索量、弹窗和无地图负例。建议独立测试集 Top-5 达到至少 95% 后继续优化配准，并同时审查各分组召回。当前只有 4 个 Hard 身份，不能宣称已跨过这个门槛。
