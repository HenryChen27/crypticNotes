# 加页手记悬浮地图助手

双击项目根目录的 `crypticNotes.cmd`（第一次用请先双击 `setup.cmd` 装依赖）。也可运行：

```powershell
python -m mapmatching.launch
```

默认只有右上角齿轮。齿轮可以按住自由拖动，松手后位置会被记住，下次启动回到原处；拖动不会误触发面板，想展开面板就原地点一下。点击展开，选择困难 / 噩梦；噩梦下显示单人 / 多人。难度、人数、等待时间都是分段开关，直接点击即可切换，不用展开下拉列表；选中项亮、未选中项暗，点已选中项不会重复触发。原图不透明度默认 30%，可在 5%～80% 调整，退出时保存。界面为冷调灰蓝雾面：面板半透明让游戏画面透出，控件是雾面浅色块配深色字，文字为浅色，整体压低对比以便融入游戏画面。正文对比度 6.7:1、控件 7.8:1 以上。

界面中文字体为汉仪第五人格体，西文与数字为 Essay Text Italic。两者随程序从 `mapmatching/assets/fonts/` 本地注册，不安装到系统，也不改动其他程序；字体缺失时自动退回 Microsoft YaHei UI。候选字体按“西文在前、中文在后”排列，Qt 逐字回退，因此同一行里的中英文会分别使用对应字体。齿轮、箭头等两个字体都不含的符号仍由系统字体提供，与改动前一致。

本地先测试：双击根目录 `本地截图测试.cmd`，选择 PNG / JPG 游戏截图；也可以在齿轮面板点击“打开本地截图测试…”。点击弹出的截图窗口，按 G 开始识别和叠图，再按 G 或 Esc 隐藏。无需打开游戏或手动绑定窗口。测试使用实际桌面截屏，截图以原宽高比显示。可以重新选图；关闭截图或点击“返回游戏模式”会停止匹配并清除叠图。请不要用其他窗口遮住截图。

命令行也可直接指定：`python -m mapmatching.launch --demo examples/0/example.png`，打开后等待手动按 G。只有自动成果展示参数 `--showcase` 会自动开始一次匹配。

进入游戏后按 G：游戏自身打开地图，助手等待默认 350 ms 后截屏，按选定模式检索、配准，并按计算得到的比例和位置显示原图。助手只观察按键，不拦截或代发 G。**按 G 即进入“打开地图状态”，这个状态一直持续到你按 Esc 或再按一次 G 为止。** 在该状态下，**每次松开鼠标左键、或滚轮停稳约 120 ms，都会自动重新匹配一次**；匹配过程中再次触发，就直接丢弃旧画面、改配最新一帧。**匹配失败不会结束这个状态**，也不会阻止下一次尝试——刚进地图时地图默认很大、一眼看不清是正常的，用滚轮缩小、或拖动地图露出更多内容，松手就会自动再试。真的一次都没配上时，提示会直接告诉你下一步该做什么（例如“可见地图内容太少，请用滚轮缩小地图后重试”）。

**在地图里单击会关掉游戏自己的小地图**，那一下松开同样会触发一次重新匹配，而这时屏幕上只剩游戏画面。助手认得出这种情况：**连续两次**都判定“屏幕上没有地图”时，会自己退出“打开地图状态”并提示“地图已关闭”。只判定一次不算数，第一次只提示“确认中…”并自动复核一遍——刚进地图还没探索时也会短暂匹配不上，一次就退太急。中途只要有一帧成功叠上，计数就清零。

有两种“匹配不上”**不算**“没有地图”，无论多少次都不会退出状态：

- **把地图放得太大**（可见结构不足）：只会一直提示你用滚轮缩小。
- **地图开着、只是还没探索**（大片灰色）：画面本身很“平”，和真正的 3D 游戏画面不是一回事。

两者靠**画面纹理**区分：3D 游戏场景实测有 320～372 个角点，而地图画面（不管探索了多少）只有 32～60 个，差 6 倍以上。地图是平面的风格化线条，3D 场景则满是纹理。所以只有画面足够“花”、同时引擎又认不出它时，才会往“没有地图”上算。

叠图之后在游戏里缩放或拖动地图，助手会自动跟着重新贴合：一旦检测到按下鼠标键或滑动滚轮，立刻先撤掉叠图（避免挡住你操作），松开按键或滚轮停稳后自动重新截屏、按记住的地图身份重算比例和位置再叠回去。所以它不是逐帧跟踪——拖动过程中叠图是隐藏的，停手才贴合。本地截图模式是静态图，不跟随，改图请点“重新识别”。窗口位置或尺寸变化仍会自动隐藏并要求重新匹配。

跟随靠 Win32 Raw Input 被动观察鼠标，只在助手自己的进程里注册，不装全局钩子、不拦截也不代发任何输入，游戏收到的操作与没有助手时完全一致。若系统拒绝了这项注册，助手会提示“鼠标监听未启用”并自动关闭跟随，其余功能照常。跟随期间按 Esc、切走窗口或换难度仍会立即停止。

识别完成后叠图可让鼠标穿透，不抢焦点。无法匹配、候选过于相似、楼层不明时显示文字，不强行叠图。当前显示的是通过初步结构筛选的**试用候选**，不表示概率已校准。

普通模式直接读取前台窗口所在的整块屏幕，无需绑定、不检查游戏标题；其他图片查看器也能测试，建议最大化展示截图。助手自带本地模式只截取自己的截图窗口，便于避免桌面干扰。助手一直读取屏幕像素，不读取游戏内存。G 不在助手面板和文件选择对话框内触发；关闭快捷键复选框可暂停。切换到其他应用会隐藏当前叠图。独占全屏尚未实测，遮挡内容会进入截屏。

识别成功后记住地图身份；再次 G 打开时只对这张地图重新求比例、位置和楼层。贴合程度不够就自动重新识别。G / Esc 隐藏时保留身份；换难度、人数、本地截图或点击“重新识别地图”时清除。记忆只在本次程序运行中有效。缓存仍是试用候选，几何相似区域可能无法单独判断是否换图，新对局可主动重新识别。

2026-09-12（目录重构）：所有和地图有关的东西收进 `maps/` 一棵树——原图按 `maps/困难|噩梦/单人|多人/` 摆放，`maps/floors.json` 是唯一的登记表，特征与索引是它的派生物。原来那两个图片目录（`加页手记地图（07.10更新）`、`凉哈皮…（08.26更新）`）和 `09.10更新` 已经删掉，里面的图一张不少地搬进了 `maps/`。**往 `maps/` 里粘贴一张图并不会让它被识别**：只有走「新增地图」登记过、在 `floors.json` 里有条目的图才参与匹配，多出来的文件安静地躺着。程序包也改名了：`map_matching_v2` → `mapmatching`（去掉了版本后缀），文档、启动器 `scripts/run.cmd`、打包脚本全部同步。**`maps/` 就在程序目录里，所以打包版也要求程序目录可写**——放在只读位置时管理列表每一行的按钮都是灰的，提示会直接说明。

2026-09-12：齿轮面板的「新增地图」改为「管理地图」——点开是完整地图列表，可按难度 / 人数筛选，逐行查看名称、难度、人数和楼层。**内置地图和自建地图不再有区别**：所有地图都在 `maps/` 这一棵树里，所以「删除」按钮已经没有，每一行只有**移除 / 恢复**。移除是**软删除**：登记条目从 `maps/floors.json` 搬进 `maps/disabled.json`，原图和特征文件原地不动，在「已停用」分组里点「恢复」就回来，恢复是瞬时的、不需要重跑特征提取。两次写入的顺序刻意设计成「先写让记录更存在的那个」，中途崩溃会留下「两边都有」的状态，而展示规则以 `floors.json` 为准判为可用，能自愈。列表只读 `floors.json` / `index.json` / `disabled.json`、不碰证据文件，所以某张图的楼层几何改过而索引还没跟上时，只把那一行标成「需重建索引」，不会把整页带崩。改动只涉及列表与索引条目的搬运，`src/` 下的识别代码和 `theme.py` 一行未动。同一天还给这两个对话框补了三件交互：与主窗口**右对齐**；**点到框外自动关闭**；管理列表里**点行身弹出该图缩略图**（按小窗尺寸解码，楼层框分色描出，点同一行或点别处收起），并让展开的设置面板在点到游戏/桌面时**自动收回成齿轮**。收「点到框外」用的是应用级事件过滤器而不是 `focusOut`：应用模态框会把框外那一下点击直接吃掉，事件走不到任何自己的控件上；而点到别的进程（游戏、桌面）时那条鼠标事件进了别人的消息队列，我们什么都收不到，只能靠 `WindowDeactivate`——所以那道判断要额外排除「失活是因为我们自己又开了个框」，否则确认框一弹出来就会把宿主对话框一起带走。

2026-09-11：修复截图中已包含助手面板时，按钮矩形被当成地图结构的问题；自动排除纵向排列的矩形控件区域，并降低模糊边界的取证权重。控件排除区域也不覆盖原图叠加。字体、灰蓝配色和分段按钮沿用用户提供的版本。汉仪中文与 Essay 英文均从项目加载，英文优先。修复齿轮位置每次重启都错位的问题：窗口显示前控件布局还没执行，齿轮的窗口内偏移被读成了尚未排版的陈旧值，导致还原出来的位置是错的、退出时又把这个错值存回去，于是每次启动都停在不同的地方。现在改为先让布局跑一遍再计算偏移，默认位置也统一按齿轮（而不是窗口）定位到右上角。新增“屏幕上没有地图”的识别：游戏里单击关掉小地图后，那次松开触发的重新匹配只会看到游戏画面，连续两次即可自动退出打开地图状态并提示“地图已关闭”。判定先看画面纹理（角点数）、再看引擎现成的可靠性门（explained、contradiction、匹配点数），阈值一个没改，只是把“不可靠”读成“这不是地图”；“放得太大”和“地图开着但没探索”都被明确排除在外。这三类画面的真实截图留在 `mapmatching/tests/fixtures/nomap/`，`tests/test_no_map_signal.py` 会跑真实引擎逐张核对。齿轮旁的提示缩短到约 1.2 秒，常见长句压成短句（完整说法仍进面板底部），提示框改为随文字长短自适应宽度——短句就是个短框，不再一律撑到 320 px；只有超过屏宽 42% 的长句才换行。

当前限制：困难截图的验证主要覆盖 1F；其他地图/2F没有同等覆盖。噩梦单人/多人 31 张原图的 2F、1F、地下室已完成原图楼层复核并支持叠图。93 个原图合成场景通过身份、楼层及叠图链路检查，但仍缺少噩梦真实游戏截图，不能把合成结果当作实战正确率。固定地图视口仍是假设，不同游戏 UI 布局也需要新截图验证。

管理地图：展开面板点「管理地图」，列出全部地图，可按难度 / 人数筛选，每行显示名称、难度·人数和楼层。列表只分「可用」和「已停用」两组——**不再有内置和自建之分**，所有地图都躺在 `maps/` 这一棵树里、进同一张登记表。因此「移除」对所有地图都是同一件事：从匹配里摘掉，原图和特征文件原地不动，之后在「已停用」分组点「恢复」就拿回来，是瞬时的（不需要重跑特征提取）。没有「删除」按钮了。新增地图的入口也收在这个对话框里：选择原图、名称、难度和人数，逐层拖框后「保存并入库」，单层图可使用「整张为此层」，无需手动重建索引。移除某难度最后一张地图时会二次提醒，此后那个模式的提示会变成「这个难度下已经没有可用地图了，请在「管理地图」里恢复或新增」。增删之后助手会重启匹配进程（约 1 秒），下次匹配生效；参见 [新增地图说明](新增地图说明.md)。

「管理地图」和「新增地图」两个框都**右对齐**主窗口，鼠标点到框外就自动关闭；展开的设置面板在点到游戏或别的程序时也会自动收回成齿轮。列表里**点击某一行的行身**（不是右侧的按钮）会在框的左侧弹出那张原图的缩略图，楼层框按 1F / 2F / 地下室分色画在上面；再点同一行或点别处即收起，点另一行直接换图。缩略图按小窗尺寸解码，不会因为原图有 4000 px 就卡一下；原图读不到时显示「原图读取失败」而不是弹错。

地图移除的边界：移除状态记在 `maps/disabled.json` 里，和 `maps/index.json` 是两回事。**重建索引不会让被移除的地图回来**——移除是把条目从登记表 `maps/floors.json` 搬进 `disabled.json`，而重建只重写 `index.json`，登记表一个字都不动（旧版靠「在侧车且不在索引里」判停用，所以重建会把它们一起恢复；这个坑现在没有了）。另一条边界还在：整棵 `maps/` 必须可写，打包版里若程序目录不可写，列表里每一行的按钮都是灰的，需要把程序解压到可写目录。

识别引擎对“看得见的内容”有硬性下限：画面里被解释出来的路口角点少于 4 个时直接放弃，4 px 内对上的角点位置少于 4 个时也判定不可靠。**把地图放得很大时可见路口本来就少，此时无论重试多少次都配不上**——这不是重试次数的问题，助手会明确提示你缩小地图。放大到极端时换算比例还可能超出引擎允许的范围（0.15～8 倍），同样无法匹配。所以“进去先缩小看一眼全貌，再放大到要看的位置”仍然是最省事的路子。

## 实测

本机 16 逻辑 CPU，显示缩放 150%。6 张原始 example：纯匹配中位约 238 ms，截图文件解码 + 匹配 + 原图变换中位约 349 ms，P95 约 441 ms。GUI 预加载约 1 秒，预加载后 G 到显示约 0.71～0.74 秒（包含 350 ms 动画等待），这项使用本地截图窗口做实际桌面截屏，尚非真实游戏帧率测试。

集成测试进程及匹配子进程合计约 400～480 MB，包含测试用截图窗口和像素校验数据；待机 5 秒抽样约占整机 CPU 0.02%～0.16%，短时抽样存在波动。匹配计算限制为一个 OpenCV 线程，按需运行。没有实测 GPU 占用和游戏 FPS，不能保证零影响。

实际屏幕上 30% 合成与离线计算的像素差 P95 为 1/255；这验证显示/DPI链路，不替代地图配准误差。原始样例的人工点配准 RMS 约 1.49～4.85 px，最大单点约 7 px。

## 复现与文件

```powershell
python -m unittest discover -s mapmatching/tests -v
python -m mapmatching.benchmarks.live_performance
python -m mapmatching.benchmarks.ui_integration
python -m mapmatching.launch --demo examples/0/example.png --showcase out/mapmatching/ui_showcase/window
```

`out/mapmatching/ui_showcase/index.html` 展示 6 张原图 30% 叠加；`performance.json` 保存逐图计时，`integration.json` 保存实际窗口检查、CPU 和内存数据。`window/panel.png` 是真实 UI 截图。

依赖清单为 `mapmatching/requirements-ui.txt`：NumPy、SciPy、OpenCV、PySide6、pywin32、psutil。双击 `setup.cmd` 会在项目下建 `.venv` 并装齐；`scripts/run.cmd` 按 `IdentityVMapAssistant.exe` → `.venv` → `pyw` → `pythonw` 的顺序自动找入口，不需要改任何路径。需要 **64 位** Python 3.13（PySide6 没有 32 位 wheel）。源码模式下配置写在项目内 `out/mapmatching/ui_settings.json`、地图库就是项目下的 `maps/`，所以**不要把项目放在 Program Files 等受保护目录**，否则首次运行写不进索引和配置。**打包版同样要求程序目录可写**：地图库 `maps/` 只有一份、就在程序目录里（配置和运行日志仍在 `%LOCALAPPDATA%\IdentityVMapAssistant`），解压到受保护目录时列表里每一行的按钮都会是灰的。启动异常写入 `out/mapmatching/ui_error.log` 并弹窗提示。启动器使用单实例锁，重复启动不会出现两个助手。
