# Android 预览版

最新发布：`0.6.11-preview`，版本代码 19。三处改动都在设置与更新路径上，识图、配准与门控一行未动：**录屏设置新增画质与帧率**（流畅／标准／高清对应最长边 720／1280／1920 像素与约 2／4／8 Mbps，帧率 24／30／60，默认仍是原来的 1280／4 Mbps／24 帧，所以没改过设置的设备录出来的文件与上一版完全一样）；**录屏默认手机声音**（`record_internal_audio` 默认值由 `false` 改成 `true`，显式点过「无声」的存量用户不受影响；未授予录音权限时不提前弹窗，改为第一次录完后提示去授权）；**更新改为后台下载**（下载搬进 `dataSync` 前台服务，离开 App 也会下完，下完自动拉起系统安装界面；那条旧路径的 `finally` 会删掉半成品，所以从前切到后台等于白下）。默认改成内部声音后，从没碰过这一项的老用户下次录制会开始带上游戏声音，也可能带上其他应用播放的媒体声——这是这次要求的默认值。

`0.6.10-preview`，版本代码 18。两处改动都在判定层，核心匹配逻辑未动：**开图判定放宽**（原先要求关闭、放大两个控件同时高分，实测关闭按钮被挡住、或截图压缩后略掉几分时，会把确实开着的地图判成“没有地图”而不叠图；现在改成一个控件强、另一个佐证，右上角关闭图标被悬浮窗遮住时还会用楼层按钮组独立确认）；**沿用上次地图时更严**（本次会话已确认过身份的地图，稀疏视野只用来重新对齐位姿，不能再用来换地图，线索不足时保留上次结果而不是改判）。

0.6.9-preview（版本代码 17）取消了高于共用算法的重复拟合门槛；楼层标签明确时仍要比较同层候选，但不再因手机压缩造成的小幅分数损失直接显示“缺少证据”。失败提示会区分结构过少、对齐不足和候选相似。版本同时包含内部声音选项、App 内录屏设置、录制花纹透明度动画和可关闭的轻触反馈。

## 本地声音与触感测试版

`0.6.7-audio-test`：录屏设置移至 App 内，悬浮窗仅保留开始／停止。声音可选择无声或内部声音（该版本默认无声，0.6.11 起改为默认内部声音），更改在下次录制生效。内部声音使用 Android 10+ Playback Capture，与原屏幕采集共用授权；需要 RECORD_AUDIO 系统权限，但不采集麦克风。它可能包含其他应用播放的媒体声音；游戏禁止第三方采集时仍可能无声。声音初始化失败会提示并保留无声录制。

音轨为 48 kHz 双声道 AAC、128 kbps。该版本里视频固定为最长边 1280、最高 24 fps、4 Mbps，不跟随系统录屏设置；0.6.11 起这三项改成可选，默认值仍是这一组。录制中悬浮花纹以 45%～100% 不透明度平滑循环，独立于匹配旋转；停止后恢复不透明。

App 的“辅助设置 → 轻触反馈”控制按钮、选择开关、关闭和悬浮球点击的系统轻触反馈，默认开启并遵循系统触感设置。自动匹配结果不震动，不申请额外振动权限。

本地测试包保留版本代码 14、原签名，可覆盖安装，也可使用 `out/rollback-before-audio-20260930/previous.apk` 回退到已验证无声版。源码备份同目录。尚未将此声音测试版发布到 Release；声音、音画同步和触感需真机验证。

## 实验：内置无声录屏

发布版本 `0.6.6-preview`（版本代码 14），内置录屏仍为实验功能。打开悬浮球设置，点击“录制操作（无声）”，结束时点“停止录制并保存”，通知栏也提供“保存录屏”。长按按钮查看说明。默认不录制，不添加麦克风权限。视频最长边不超过 1280，目标最高 24 fps、4 Mbps，实际性能需真机验证。

Android 10 及以上保存到相册 `Movies/CrypticNotes`；Android 8/9 保存到应用的外部 Movies 目录。旋转屏幕会结束并保存当前视频；停止服务也会尝试完成保存。系统强杀或设备断电不保证当前视频可恢复。

录屏与识图共用同一个 MediaProjection 和 VirtualDisplay：录制时接入 GPU 分流，分别输出至识图 ImageReader 和视频编码器；停止后恢复直接输出 ImageReader。录制失败不主动停止识图。识图截图时临时隐藏叠图的过程可能出现在录像中，尚未做录像专用合成补偿。

授权改为系统默认选择：支持单应用共享的系统可以选择游戏，不再由代码强制共享整个屏幕。单应用通常不含其他应用的悬浮窗，录制完整叠图演示请选择整个屏幕。当前只支持与屏幕比例接近的全屏游戏，分屏或自由窗口比例不符时暂停叠图，避免坐标错位。单应用共享仍占用采集会话，不能解决与另一个系统录屏的冲突。

回退点位于 `out/rollback-before-recording-20260930`，包含改动前 APK、源码压缩包和回退说明。本地实验包保留版本代码 13；手机更新发布版已提高为 14。发布版需要回退时，从备份源码构建更高版本代码、同签名的回退修复包，避免卸载丢失设置。

启动主界面时会在后台检查一次发布版本，仅读取 GitHub Release 与安卓版本清单，不自动下载或安装。发现新版后，“应用更新”折叠栏显示柔和红点，折叠时也可见；点击更新按钮才开始下载。网络失败不弹窗打断使用，也不误报“已是最新版本”。

悬浮球支持：单击开关设置、双击重新识别、拖动移动、长按停止识别。双击（`retryFromBadge()`）会撤销旧叠图、把 `lastGateAt` 清零并立刻排一次检测，也就是**把「再等一轮 800 毫秒」这件事交给玩家手动触发**；它不绕过门控——地图没展开时依旧只得到拒识，核心判定一行未动。双击同时会解除「隐藏叠图」，因为「现在给我看地图」是它的本意。为区分单双击，单击设置要等一个系统双击判定间隔（约 300 毫秒）才生效。长按阈值是 `BADGE_HOLD_MS = 900` 毫秒，**特意长于系统的 500 毫秒**：四个手势共用一个很小的目标，而这是唯一具破坏性的那个，宁可要求按住久一点，也不该被一次「按久了的点击」误触。

这是独立安卓客户端，不改变 Windows 发布版。用户在游戏中点击原本的地图入口，客户端根据屏幕画面自动检测、匹配和叠图，无需键盘快捷键。

## 当前实现

- 原生 Android 设置页、屏幕采集前台服务、可穿透的半透明叠图，界面沿用桌面版的磨砂毛边与斜向渐变。
- 内置 73 张地图，通过 Chaquopy 调用原有 Python 核心，不改检索、配准及接受阈值。
- 先检测地图界面，再等待画面稳定，不依赖手指是否还按着屏幕。
- 多人专用模板失败后使用原有单人模板回退逻辑。
- 转屏、锁屏、停止授权时隐藏叠图；通知栏停止服务。
- 游戏内入口是可自由拖动的**常驻**小圆钮，只显示白色纹章。纹章由 `scripts/make_emblem.py` 从 `scripts/assets/emblem-source.png` 生成（亮度当透明度、全部涂白，所以只剩白色部分）。**识别中纹章持续旋转**（`ObjectAnimator`，1100 毫秒一圈）代替“正在识别…”文字。**识别结果做成气泡**：`bubble(true/false)` 在 200 毫秒里把窗口宽度从圆钮尺寸动画到文字条尺寸，标签同步淡入，所以看着像从球里冒出来——球在右半屏时气泡向左长（`bubbleLeft`），纹章留在原处而不是被气泡顶走；气泡是左右羽化的矩形（`Theme` 的 `"band"` 形状），基础宽 220dp 并随机型与尺寸缩放。提示约 1.8 秒后自动收回；开始拖动时用 `collapseBadgeNow()` **立刻**收起（动画版会每帧按旧锚点重设 `badgeParams.x`，和手指抢位置），拖动锚点取球心而非窗口左边，否则气泡展开时按下会差一个条宽。**点击开关设置面板，拖动移动，长按关闭识别**（`stopRecognition()`：撤叠图、收按钮、`stopSelf()`，避免留下一个看不见却仍在采集的服务）。旋转屏幕时退出面板，避免旧尺寸使按钮越界。
- 按钮尺寸由「悬浮球尺寸」设置决定（70%–160%，默认 100%，键为 `mobile` 首选项的 `badge_scale`）：圆钮、纹章、内边距与气泡高度一起缩放，气泡宽度也随尺寸走并在屏幕边缘截断。
- 游戏设置面板是横屏一次放得下的小面板：标题 17dp、字段 14dp、选项与按钮 42dp 高，标题上方留 12dp 内边距，关闭是右上角独立的 `Theme.CloseButton`（叉），底部固定一行三个等宽按钮——「重新识别」「隐藏／显示叠图」「小地图区域」。面板本身不再滚动，内容区套 `ScrollView` 以防小屏。面板与球分居上下两半（`ballBelow`），因为面板窗口不带焦点（`FLAG_NOT_FOCUSABLE` 隐含 `FLAG_NOT_TOUCH_MODAL`），面板外的点击会落到球上，所以「再点一下球」才真能关掉面板。「隐藏叠图」置 `overlayHidden`，`showOverlay()` 与 `sample()` 一起遵守，识别继续跑但不上屏。
- 面板里的难度与参考路线**改动即生效**：`applyRecognition()` 立刻写首选项并在工作线程重建匹配器（约 0.7–1.1 秒），面板里的状态行显示「正在应用…／已应用：噩梦 · 单人路线」。此前重建只挂在「重新识别」按钮上，改完难度直接关面板等于什么都没发生。重复改动用 `applyToken` 只让最后一次汇报，重建期间 `ready=false`，避免匹配与重建并发。
- 首页把「开启自动识图」放在最上面且在折页之外，占主体、常驻；其余设置折进一栏「游戏设置」，与桌面端一致，点标题展开／收起，折叠态是阅读偏好所以不持久化。**默认展开**——它在默认收起期间整栏消失过两次，现在开机就把设置摆在明面上。栏内按使用频率排列：难度、参考路线、叠图不透明度、悬浮球尺寸、点击区域触发、地图管理、重置悬浮球位置、说明文字。
- 折叠栏的标题与内容**必须**由 `MainActivity.fold(title, expanded)` 一次建成（它内部 `content.addView(bar)` + `content.addView(body)`）。曾经这两半是各调用点手写拼的，漏掉标题那行 `addView` 就得到一个没有栏的折叠栏：屏幕上看不见、点不到，而编译、lint、运行都不报错——「游戏设置」这样消失过两次，期间首页的难度／尺寸／地图管理全部无法进入。`android/tests/home_fold.py` 是源码级绊线（不是 UI 测试）：它断言折叠栏只在 `fold()` 里造、且 `fold()` 两半都挂上了，任何绕过 `fold()` 的手写折叠栏都会让它失败。`python android/tests/home_fold.py` 可在无设备时跑。
- 检查应用更新不再有进度条（`Theme.ChalkProgress` 已删除）：按钮下方是一个 `Theme.Spinner`——就是那颗纹章在转（共用 `R.drawable.floating_emblem`，同样的 1100 毫秒一圈），下载百分比只走状态文字。下载本身跑在 `UpdateService` 里，首页只是它的一个观察者（`UpdateService.observe`，`onPause` 注销），所以回到首页时会先画一次 `statusText()` 把当前状态接上，而不是从空白开始。
- 「重置悬浮球位置」只删掉 `badge_x`/`badge_y`，下次启动回到默认角落。**尺寸与不透明度的改动立即生效**：首页滑杆写偏好后调 `CaptureService.current.applyDisplayPreferences()`（服务与首页同进程、同在主线程，所以直接调用而不是发 Intent），不必重启识别。`current` 是 `static`，带 `@SuppressLint("StaticFieldLeak")`——它是个 Service，不是会泄漏的 Context，与 `TapRelayService.current` 同一写法。
- 平时仅显示小按钮，状态变化时短暂显示消息，约 1.8 秒后收回；重复文字不重复弹出。截图副本里遮去悬浮按钮，画面比较排除其位置，不为截图反复隐藏按钮。
- 显示叠图时每 200 毫秒检查视口及右侧地图控件变化。拖动、换层或关闭使画面变化时撤下旧图，再验证地图界面与配准；另有 800 毫秒独立门控检查兜底。异步结果已过期或截图已移动时，不显示旧结果。
- 定期检查只验证叠图区域之外的地图控件，不隐藏叠图，也不把带叠图的截图送去配准。仅在移动、换层等导致旧图失效时撤下重算。状态条遮住一个控件时验证另外两个；若遮住多个控件则保守拒绝，可将状态条移开。
- 限制送入算法的截图宽度到 1440；识图单线程，降低与游戏争抢 CPU。PNG 编码放在工作线程，不占主线程。
- 同一帧只解码一次：画面门控在 Java 侧先跑，`match(..., gated=True)` 就不再重复门控。这个捷径只在“同一份帧字节”上成立，所以只有 Java 已经门控通过才传真值；门控没通过时根本不调用 `match`。
- 首页的“地图管理”是只读列表，按难度／路线筛选并可搜索，点任意一行可看地图底图预览；不提供增删改，地图库仍以 `maps/floors.json` 为准。

## 尚未完成的验证

开图门控已从「关闭、放大两个控件同时高分」放宽为「一个控件强、另一个佐证」（`min >= .75` 且 `max >= .85`，方法标记 `corroborated_map_controls_v2`）。放宽的起因是实测有真实开图帧落在旧阈值之外；关闭图标被悬浮窗挡住时，允许在放大控件 >= .90 的前提下改用楼层按钮组独立确认（用 UI 控件，不用地图几何）。使用用户提供的 6 张截图：3 张展开画面均通过，3 张正常游戏／拾取面板画面均拒绝。这只是样本测试，不代表手机实机覆盖率；`android/tests/bridge_contract.py` 把它固化成可重跑的检查，但样本限制不变。第三张地图（`open-0`）探索较少，匹配候选尚无人工真值，当前结果是弃权（手机上显示为“没匹配上，多走几步再试”），不能声称配准精度已验证。核心的判定与句子没动，`mobile_bridge.py` 的 `PHONE_TEXT` 只把同一结论换成一个手机文字条放得下的说法；改的是措辞，不是结论。

小圆钮可以拖到屏幕任意位置，这是上一轮刻意去掉 x<.41 夹取后的行为。副作用没有解决：截图副本里遮掉小圆钮用的是一块黑色矩形，而 `mobile_bridge.match` 只把 x .41–.86 之外清零、视口内原样送进配准，所以把小圆钮拖进配准视口时，那块黑矩形就成了配准输入。影响没有量化，也没有为此改核心匹配逻辑，需要实机确认；稳妥做法是把它留在左侧。

此外，Android 可用的依赖版本为 Python 3.10、OpenCV 4.5.1、SciPy 1.8.1，与桌面版不同；算法源文件一致不代表数值结果已经通过手机回归测试。

叠图生命周期与界面通过编译和静态检查。`android/tests/replay_frames.py` 调用生产 Java 比较代码，验证截图开关变化、模拟平移和状态条排除；不覆盖 Android 系统截图时序与真实换层，仍需手机实测。隐藏取帧等待设为 110 毫秒，具体设备是否足够需要验证。

本轮改的界面只过了编译与 lint（0 error，warning 全是既有的那几类）。**没有设备，以下全部没在真机上跑过，如实记在这里**：气泡展开/收回的动画观感与 1.8 秒时长是否合适；展开时点球能否可靠关面板（依赖面板外点击穿透到球）；横屏小屏上面板是否真的不用滑动；拖动时「立刻收起」是否消除了抢位抖动；首页改尺寸/不透明度时球是否当场变化；转圈纹章在深色游戏画面上的可见度；**双击的判定窗口**——`ViewConfiguration.getDoubleTapTimeout()` 是系统值（通常 300 毫秒），在游戏里手指是否够快、误触率如何，只有真机能定；单击要等这个窗口才打开面板，这个延迟是否碍事同样未知。这些都需要一次真机试玩才能判定。

`android/tests/bridge_contract.py` 打印电脑上的缓存配准及整图检索耗时，不能当作手机耗时。移动时先撤下旧图，稳定后重新配准，不是逐帧跟随手指的连续动画。

**0.6.11 的三项改动同样一项都没在真机上跑过**，只验到「编译通过 + 源码级契约 + 不破坏既有护栏」。能离线确定的到此为止，下面这些只有真机能定：

- **画质与帧率档位**：`SharedScreenRecorder.chooseVideoFormat()` 有一级降级阶梯（尺寸不支持就降一档画质、帧率不支持就夹到该尺寸支持的范围、全都不行才抛原来的异常），但这条路径只有在真机上才会走到，没有被执行过。三档分辨率与三档帧率在具体机型上是否被编码器接受、降级提示是否会误报，都要实机确认。
- **60 帧的实际表现**：流畅度、发热、掉帧，以及 8 Mbps 下文件有多大。
- **后台下完能否真的弹出安装界面**（见上文“手机内更新”）。被拦下时只会得到通知，不报错，所以也无法从日志判断成败。
- **`Range` 续传对 GitHub 资源 CDN 是否有效**：若不返回 206，代码会退回整包重下，功能仍正确，只是白费流量。
- **默认内部声音是否真的录到了游戏声**，以及录音权限被拒时那条提示是否足够醒目（提示出现在第一次录完之后）。

录屏设置的三行（声音／画质／帧率）与「应用更新」栏只过了编译与 lint（0 error）；`android/tests/update_contract.py` 是源码级绊线，它断言 manifest 声明了 `dataSync` 前台服务、全仓库只有 `UpdateService` 一处写下载文件、`AppInstaller.verify` 排在改名之前、安装 Intent 带 `FLAG_ACTIVITY_NEW_TASK`，以及 `AppUpdater` 里不再有 `FileOutputStream`／`renameTo`／`MessageDigest`。

此版本还没有移植桌面布偶动画、地图录入和记录目录设置。不要替换现有正式 Release，也不要宣传成已经完成实机验证的手机正式版。

## 手机与电脑的差别

- Android 需要用户明确授予悬浮窗权限和每次会话的屏幕采集权限。
- Android 14 及以上请求分享整个屏幕，避免单应用捕获窗口尺寸与悬浮坐标不一致。
- 横屏方向、刘海、系统导航栏、游戏内安全边距都会影响坐标，需要实机校准。
- Android 12 以后对穿透悬浮窗有透明度限制，叠图窗口默认 30%，最高 70%。
- 系统可能回收后台服务；本应用不自行绕过系统权限或电池管理。
- 默认不依赖无障碍服务；可选的“点击区域触发”需要无障碍手势权限，仅转交用户在框选入口范围内的触摸，不读取窗口内容或游戏内存。
- 地图库复制到应用私有目录；清除应用数据或卸载会删除该目录。

## 构建

工具隔离在 `out/android-tools`，不提交到 Git。使用 `scripts/prepare_android.py` 暂存核心与地图。Android Gradle 项目在本目录。APK 首先以 preview 调试签名构建，正式分发前需固定发行签名并完成真机验证。

构建必须先 `python scripts/prepare_android.py`，然后：

```bash
JAVA_HOME="C:/jysj/out/android-tools/jdk/jdk-17.0.20.1+1" \
ANDROID_USER_HOME="C:/jysj/out/android-user" \
GRADLE_USER_HOME="C:/jysj/out/android-gradle-cache" \
  ./out/android-tools/gradle/gradle-8.13/bin/gradle -p android assembleDebug --console=plain
```

`ANDROID_USER_HOME` 不能省。调试签名钥匙存放在 `out/android-user/debug.keystore`；漏掉这个变量，Gradle 会回退到 `~/.android` 并**另造一把钥匙**，打出的 APK 因为签名不同无法覆盖安装到已装设备上，只能在手机上卸载重装（会连带清掉点击区域校准）。改完签名相关的设置后如果 Gradle 报全 up-to-date，删掉 `android/app/build/outputs/apk/debug/app-debug.apk` 再构建，否则 APK 不会重新签名。签好之后用 `out/android-tools/sdk/build-tools/*/apksigner.bat verify --print-certs` 核对证书是不是 `b7b3d824…`（`apksigner` 需要 `JAVA_HOME`，和构建一样指到 `out/android-tools/jdk`）。

改过 `mobile_bridge.py` 或 `mobile_gate.py` 之后，不需要设备就能先跑一遍桥接契约检查：

```bash
python android/tests/bridge_contract.py
```

它用 `out/android-samples` 的 6 张截图核对门控判定（3 关 3 开），并断言 `gated=True` 在每个门控通过的帧上和 `gated=False` 结论一致——这条断言是防“捷径让本该被拒的帧混进匹配”的。同时打印冷启动与缓存命中的耗时。

## 点击区域校准

1. 开启屏幕采集，回到游戏横屏界面。
2. 长按状态条进入游戏设置，点击“校准地图入口”。
3. 框住左上角实际地图入口，点击保存；提供默认和取消按钮。
4. 如果想让点击直接触发识图准备，先在首页开启“点击区域触发”，并在系统中授予对应手势权限。没开启时，框选位置仍可保存，但工作方式是画面自动检测。

校准界面会临时接管触摸，保存／取消后退出。不要框进移动摇杆或其他操作键。此预览版暂不支持同时多指触摸该校准区域，点击转交有少量延迟。自动画面检测始终保留，点击不能绕过地图展开验证。

## 手机内更新

首页点击“检查应用更新”，先读取同一 GitHub 最新 Release 的 `android-update.json` 小型版本清单，与本机 `versionCode` 比较。只有存在新版才下载 `IdentityVMapAssistant-Android-arm64.apk`，不会下载 Windows 包。

**下载在后台进行，可以离开这个页面。** 清单核对通过后，首页把地址、大小、SHA-256 和版本号交给 `UpdateService`（`dataSync` 前台服务，通知栏显示百分比并持有部分唤醒锁），自己只负责显示进度。这与上一版不同：以前下载跑在首页的一个裸线程里，`finally` 会删掉半成品，所以切到后台等于白下。半成品写在 `cacheDir/update.download`，中断后下次带 `Range` 续传——但只在服务器真的返回 206 时才续，返回 200 就从零重来。**系统强杀进程或用户“强行停止”不会自动续传**，只能下次重试或从头再来。

下载完成、校验通过（字节数、SHA-256、包名与签名与现装一致、`versionCode` 与清单一致）之后才改名为 `cacheDir/update.apk`，然后打开系统安装界面。安装动作收敛在 `AppInstaller` 一处，`AppUpdater` 与 `UpdateService` 都调它，避免两份实现逐渐漂移。首次需允许本应用安装更新，之后仍需系统安装确认。安装前停止采集，安装后重新开启识图。这不是静默安装或绕过 APK 的热更新。

“下载完自动弹出安装界面”**不是保证**。Android 10 起从后台启动界面会被系统静默拦下（不抛异常，代码察觉不到），本应用靠悬浮窗权限争取这个豁免，但没有设备能证实它一定生效。因此每条路径都留了可点的东西：进度通知结束时换成一条“更新已下载，点按完成安装”的通知，`update_pending_install` 也会记进偏好，下次回到首页自动补装一次（只补一次，取消系统安装对话框后不会反复弹）。安装包留在缓存目录，`UpdateProvider` 只把它以只读方式交给系统安装器。

发布者每次提高 `versionCode`，使用同一签名构建，再运行 `python scripts/publish_android.py`。脚本替换现有 Release 的安卓包，核对远端 SHA-256 后最后发布版本清单，保留 Windows 附件，不新建 Release。内置地图随 APK 更新，升级时刷新应用私有目录中的资源。首次安装本版仍需安装 APK，之后直接在手机首页检查更新。

联网仅用于主动检查和下载更新，不上传游戏截图。网络或校验失败保留现有安装，可稍后重试。

### 首次启动

首次启动会准备地图库、加载识图引擎，期间悬浮球仍可打开设置和拖动，设置内显示准备阶段。准备完成后自动开始检测，无需重启。通知和屏幕采集授权依次出现；不允许通知也可继续申请屏幕采集。

### 手机匹配策略

不以探索面积或固定探索比例决定是否叠图。少量但独特的结构也可以通过；轮廓对齐不足、候选地图难以区分时暂不叠图。标准横屏布局下，明确高亮的楼层按钮会限制搜索楼层；无法可靠读取时不猜楼层。这些仍是几何启发式检查，不代表识别一定正确。

手机版复用几何评分，但独立执行放行规则；已排除 HUD 的截图不再重复尝试桌面裁剪。候选检索最多均匀采样 192 个描述点，限制成对计算量，原图解码只缓存当前地图。测试耗时是开发机算法耗时，不代表手机端到端延迟。

### 与系统录屏同时使用

Android 可能在另一项屏幕采集开始时终止当前采集，因此不保证与手机系统录屏并行。内置录制与识图复用同一次屏幕采集（一个 MediaProjection 分流到识图 ImageReader 和视频编码器），不另申请采集会话，所以与系统录屏冲突的原因只剩系统本身对同时采集的限制。
